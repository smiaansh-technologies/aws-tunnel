## 0. PROJECT IDENTITY & NON-NEGOTIABLE CONSTRAINTS

- **App name**: `aws-tunnel` (user-facing)
- **Entry point**: `main.py` (Tkinter GUI). There is no web server, no API.
- **Single source of truth for version**: `config.py` → `APP_VERSION = "X.Y.Z"`
- **Data locations**: App settings/logs live in `~/.aws-tunnel/`.
  NEVER write app data inside the repo directory.
- **Credential rule**: The app NEVER stores, logs, or serializes AWS
  credentials, SSO tokens, private keys, or access keys. It relies on the
  AWS CLI's own cache at `~/.aws/sso/cache/` for token status.
- **Dependencies**: Keep runtime deps minimal. New pip packages require
  explicit justification in the change description. stdlib is always
  preferred when possible (e.g. `urllib` over `requests` for a single
  JSON endpoint).

## 2. SECURITY — ZERO TOLERANCE FOR LEAKS

### 2.1 Never Commit Real Identifiers or Credentials

Scan your diff BEFORE considering a task done. The following are
**FORBIDDEN** anywhere in versioned files (source, fixtures, docs,
screenshots, scripts, PowerShell samples):

| Pattern | Example | Substitute with |
|---|---|---|
| AWS account IDs (12 digits) | `886436937316` | `111122223333` or `000000000000` |
| SSO directory IDs | `d-9f676e80c8` | `d-xxxxxxxxxx` |
| EC2 instance IDs | `i-0fceb6b5025641e8b` | `i-0123456789abcdef0` |
| RDS / Redshift / hostnames containing real project names | `mydb.cfqc46c8e59z…` | `mydb.cluster-xxxx…` or placeholders |
| Real profile names / account aliases | `production`, `jambocard` | `dev`, `staging`, `my-profile` |
| AWS access keys | `AKIA…`, `ASIA…` | **DO NOT MOCK THESE AT ALL** — use empty strings or a comment |
| Private keys / PEM blocks | `-----BEGIN RSA…` | Never include, even "sample" ones |
| Passwords / tokens in code or fixtures | `password = "secret123"` | Use `"***REDACTED***"` or `None` |

### 2.2 Sanitization Workflow

If you need to add example data (fixtures, sample scripts, test data):

1. Use only the placeholder values from the table above (or equivalent
   obviously-fake ones).
2. After writing, grep the repo for the real-identifier patterns (run a
   search for `AKIA`, `ASIA`, `-----BEGIN`, 12-digit standalone numbers
   that aren't port numbers, etc.) and confirm zero matches outside
   `.venv/`, `build/`, `dist/`.
3. Screenshots generated by `scripts/capture_screenshots.py` must
   **only** use mocked/placeholder data — never point the capture script
   at real `~/.aws` config or real AWS credentials.

### 2.3 .gitignore Hygiene

The repo `.gitignore` is authoritative. NEVER commit:

- `.venv/`, `venv/`, `env/` (any virtualenv)
- `build/`, `dist/`, `*.spec~`, PyInstaller work directories
- `aws-tunnel.exe`, `*.exe`, `*.app`, `*.so`, `*.dylib`, `*.pyd`
- `.pytest_cache/`, `.coverage`, `coverage.xml`, `.mypy_cache/`
- `__pycache__/`, `*.py[cod]`
- Any file containing secrets (use `settings.json` placeholders instead;
  the real `settings.json` lives in `~/.aws-tunnel/` anyway and
  is NOT in the repo).
- `*.local.ps1` (any user-specific PowerShell scripts with real IDs; keep
  local-only overrides outside versioning via .gitignore's `*.local.ps1` pattern
  so users can safely fill in real account/instance data without committing).

## 3. GUI / TKINTER CODE RULES

### 3.1 Thread Safety (Non-Negotiable)

- **All Tk widget operations (read or write) must run on the main
  thread.** If you perform work on a background thread (network I/O,
  long-running subprocess, etc.), you MUST marshal any UI update back
  to the main thread via `root.after(0, callback, *args)`.
- The pattern is:
  ```python
  def worker():
      result = do_expensive_work_off_main_thread()
      root.after(0, update_ui_with_result, result)
  threading.Thread(target=worker, daemon=True).start()
  ```
- Background threads should always be `daemon=True` so they don't block
  app exit.

### 3.2 Subprocess Spawning — Console Windows on Windows

- Every `subprocess.run` / `subprocess.Popen` that launches AWS CLI,
  `taskkill`, or any other console-subsys program MUST pass
  `**no_window_kwargs()` from `process_utils.py` on background /
  non-interactive calls.
- Exception: if the user explicitly requested an interactive console
  (e.g. an SSM shell session that should appear in its own window),
  use `new_console=True` WITHOUT `CREATE_NO_WINDOW` — see the pattern
  in `tunnel/ssm_tunnel.py:_process_start_kwargs`.
- Never call the raw `CREATE_NO_WINDOW` constant directly; go through
  the `no_window_kwargs(extra_flags=…)` helper so macOS/Linux get `{}`
  and the Windows flag logic lives in one place.

### 3.3 UI Changes Require Documentation Regeneration

If a change affects any of these, regenerate both artifacts before
finalizing:

| Change type | Regenerate | Command |
|---|---|---|
| Preferences dialog, any menu text, profile wizard, bastion dialog, tunnel panel, About dialog | User-guide screenshots (10 PNGs) | `python scripts/capture_screenshots.py` |
| Any change to screenshots OR edits to `docs/user_guide.html` | PDF manual | `python scripts/build_docs_pdf.py` (needs Playwright + chromium) |

## 4. CODE QUALITY & TESTING

### 4.1 Test Requirement

- For bug fixes: add at least one test that fails on the old code and
  passes after the fix (regression test).
- For new features: add tests covering the public API surface of the
  new module(s). Pure GUI code (layout, widget positioning) is
  exempted from unit tests but the logic it wires to is not.
- Full test suite MUST pass before finalizing:
  ```
  .venv\Scripts\python.exe -m pytest -q      # Windows
  ./.venv/bin/python -m pytest -q            # macOS/Linux
  ```
- If a failure is unrelated to your change, document why in your
  response; do not silently skip failing tests.

### 4.2 Architecture & Import Direction

The module hierarchy is:

```
main.py (GUI wiring + menus)
  ├── gui/            (Tk code only — never imports boto3 or calls AWS)
  ├── aws/            (SSO profiles, login, bastion discovery — pure AWS SDK / CLI wrappers)
  └── tunnel/         (SSM + SSH tunnel logic, process management)
config.py             (paths, Settings — importable by everyone, imports nothing else from project)
process_utils.py      (subprocess helper — importable by everyone, no project-local deps)
logging_setup.py      (one-shot log config — runs at startup)
```

- `gui/` modules **must NOT** import `boto3` or make AWS calls directly.
  They go through the `aws/` and `tunnel/` modules. This is what lets
  the logic be unit-testable without a display or credentials.
- `config.py` is the root — it must never import from `aws/`, `tunnel/`,
  or `gui/`.

### 4.3 DRY & Shared Helpers

Before writing a new utility function, search the repo for prior art:

- Subprocess flags → `process_utils.no_window_kwargs()`
- Input validation for hostnames/ports → `tunnel/validation.py`
- Settings persistence → `config.Settings.load()/.save()`
- Timestamp-based scheduling/interval math → see patterns in
  `update_checker.py` (`INTERVALS`, `is_check_due`, `record_check`)

## 7. CHECK-FOR-UPDATES FEATURE — MAINTENANCE RULES

- Feature lives in three places:
  1. `update_checker.py` — pure stdlib logic (no Tk, no side effects on
     files/network beyond the single GET to `api.github.com`).
  2. `main.py` — `_start_check`, `_handle_check_result`,
     `_schedule_next_auto_check`, `auto_update_tick`, Help > Check for
     Updates… menu item, Preferences row for the interval, startup
     hook `auto_update_tick()` before `root.mainloop()`.
  3. `config.py` — `GITHUB_REPO`, `Settings.update_check_interval`,
     `Settings.last_update_check`.
- `GITHUB_REPO` defaults to `None` — this is intentional. Update the
  assignment to `"owner/repo"` (e.g. `"kamal/aws-tunnel"`) only
  after the repo is actually published on GitHub under that slug. Until
  then, the feature gracefully no-ops in auto mode and shows an
  informational dialog in manual (Help menu) mode.
- Never point the check endpoint anywhere other than the official
  GitHub REST API (`api.github.com/repos/<owner>/<repo>/releases/latest`).
  No redirects, no custom mirrors, no CDN.
- Network calls always use `timeout=10` (or similar) and a User-Agent
  of `f"{APP_NAME}/{APP_VERSION}"` — keep these.
